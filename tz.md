### 1.1. ПРОЦЕСС: СОЗДАНИЕ ХОСТЕС/МОБИЛЬНОГО ПРОДАВЦА
**🔄 ИЗМЕНЕН** - добавлена генерация пароля и отправка на email + сброс пароля

```mermaid
sequenceDiagram
    participant Admin as Администратор
    participant AdminPanel as Админка
    participant Backend as Backend
    participant OneC as 1С
    participant Email as Email сервис

    Admin->>AdminPanel: Авторизация в админке
    
    Admin->>AdminPanel: Создание нового пользователя
    
    AdminPanel->>Admin: Форма создания:<br/>- ✅ Email (будет использован как логин)<br/>- Тип: [Хостес/Мобильный продавец]
    
    Admin->>AdminPanel: Заполнение данных
    
    alt Тип: Мобильный продавец
        AdminPanel->>OneC: Запрос списка сотрудников
        OneC->>AdminPanel: Список сотрудников
        AdminPanel->>Admin: Выберите сотрудника из 1С
        Admin->>AdminPanel: Выбор сотрудника
        
        AdminPanel->>OneC: Запрос складов сотрудника
        OneC->>AdminPanel: Список складов
        AdminPanel->>Admin: Выберите склад
        Admin->>AdminPanel: Выбор склада
        
    else Тип: Хостес
        Note over AdminPanel: Привязка к сотруднику 1С не требуется
    end
    
    Admin->>AdminPanel: Сохранить
    
    Note over Backend: ✅ ГЕНЕРАЦИЯ ПАРОЛЯ
    AdminPanel->>Backend: Создание пользователя<br/>{email, type, employee_id, warehouse_id}
    
    Backend->>Backend: Генерация безопасного пароля<br/>(12+ символов, буквы, цифры, спецсимволы)
    
    Backend->>Backend: Сохранение учетных данных<br/>Логин: email<br/>Пароль: сгенерированный (хешированный)<br/>✅ Логирование: создание пользователя
    
    Note over Backend,Email: ✅ ОТПРАВКА ПАРОЛЯ НА EMAIL
    Backend->>Email: Отправка письма на email пользователя<br/>Тема: Доступ к мобильному приложению<br/>Текст:<br/>Ваш логин: [email]<br/>Ваш пароль: [сгенерированный пароль]<br/><br/>Ссылки на скачивание:<br/>App Store: [ссылка]<br/>Google Play: [ссылка]
    
    Email->>Email: Отправка письма
    
    Backend->>AdminPanel: Пользователь создан
    
    AdminPanel->>Admin: ✅ Пользователь создан<br/>Логин (Email): [email]<br/>Тип: [Тип]<br/><br/>⚠️ Пароль отправлен на email пользователя
    
    Note over Admin,AdminPanel: ✅ НОВОЕ: СБРОС ПАРОЛЯ
    Admin->>AdminPanel: Список пользователей
    Admin->>AdminPanel: Выбор пользователя → Сбросить пароль
    
    AdminPanel->>Admin: Подтвердите сброс пароля для [email]
    Admin->>AdminPanel: Подтверждение
    
    AdminPanel->>Backend: Запрос сброса пароля<br/>{user_id}
    
    Backend->>Backend: Генерация нового пароля<br/>(12+ символов)
    
    Backend->>Backend: Обновление пароля в БД<br/>(хешированный)<br/>✅ Логирование: сброс пароля
    
    Backend->>Email: Отправка письма с новым паролем<br/>Тема: Ваш пароль был сброшен<br/>Текст:<br/>Ваш новый пароль: [новый пароль]
    
    Email->>Email: Отправка письма
    
    Backend->>AdminPanel: Пароль сброшен
    
    AdminPanel->>Admin: ✅ Пароль сброшен<br/>Новый пароль отправлен на email пользователя
```

**Изменения:**
- ✅ **Логин = Email** пользователя
- ✅ **Автоматическая генерация пароля** (безопасный, 12+ символов)
- ✅ **Отправка пароля на email** (админ не видит пароль)
- ✅ **Письмо содержит:** логин, пароль, ссылки на скачивание приложения
- ✅ **Сброс пароля** - админ может сбросить пароль любому пользователю
- ✅ **Логирование** - создание пользователя и сброс пароля логируются

### 1.2. ПРОЦЕСС: СПРАВОЧНИК ТОРГОВЫХ ТОЧЕК
**🔄 ИЗМЕНЕН** - добавлено мягкое удаление, уникальность названия, визуализация карты

```mermaid
sequenceDiagram
    participant Admin as Администратор
    participant AdminPanel as Админка
    participant Backend as Backend
    participant DB as База данных
    participant Map as Карта (Google Maps/Yandex Maps)

    Admin->>AdminPanel: Авторизация в админке
    
    Admin->>AdminPanel: Управление торговыми точками
    
    AdminPanel->>Backend: Запрос списка торговых точек
    Backend->>DB: Получение списка точек (включая неактивные)
    DB->>Backend: Список точек
    Backend->>AdminPanel: Список торговых точек
    
    Note over AdminPanel,Map: ✅ ВИЗУАЛИЗАЦИЯ КАРТЫ
    AdminPanel->>Map: Запрос карты с маркерами
    Map->>AdminPanel: Карта с маркерами всех точек<br/>(активные - зеленые, неактивные - серые)
    
    AdminPanel->>Admin: Список точек + Карта:<br/>- Название (уникальное)<br/>- Город<br/>- Координаты<br/>- Статус: [Активна/Неактивна]<br/>- Доступна для хостес<br/>- Доступна для мобильных
    
    alt Создание новой точки
        Admin->>AdminPanel: Создать новую точку
        
        AdminPanel->>Admin: Форма создания:<br/>- ✅ Название торговой точки (уникальное)<br/>- Город<br/>- Координаты (широта, долгота)<br/>- ☑️ Доступна для хостес<br/>- ☑️ Доступна для мобильных продавцов
        
        Admin->>AdminPanel: Заполнение данных
        Admin->>AdminPanel: Сохранить
        
        AdminPanel->>Backend: Создание точки<br/>{name, city, coordinates, hostess_access, seller_access}
        
        Backend->>DB: Проверка уникальности названия
        
        alt Название уникально
            Backend->>DB: Сохранение точки<br/>Статус: active<br/>✅ Логирование: создание точки
            DB->>Backend: Точка создана
            Backend->>AdminPanel: Точка создана
            
            AdminPanel->>Admin: ✅ Торговая точка создана
            
        else Название уже существует
            Backend->>AdminPanel: Ошибка: название уже используется
            AdminPanel->>Admin: ❌ Название точки должно быть уникальным
        end
        
    else Редактирование точки
        Admin->>AdminPanel: Редактировать точку
        
        AdminPanel->>Admin: Форма редактирования:<br/>- Название (уникальное)<br/>- Город<br/>- Координаты<br/>- ☑️ Доступна для хостес<br/>- ☑️ Доступна для мобильных
        
        Admin->>AdminPanel: Изменение данных
        Admin->>AdminPanel: Сохранить
        
        AdminPanel->>Backend: Обновление точки<br/>{location_id, updated_fields}
        
        Backend->>DB: Проверка уникальности названия (если изменено)
        
        alt Название уникально или не изменено
            Backend->>DB: Обновление данных<br/>✅ Логирование: изменение точки
            DB->>Backend: Данные обновлены
            Backend->>AdminPanel: Точка обновлена
            
            AdminPanel->>Admin: ✅ Торговая точка обновлена
            
        else Название уже существует
            Backend->>AdminPanel: Ошибка: название уже используется
            AdminPanel->>Admin: ❌ Название точки должно быть уникальным
        end
        
    else ✅ Мягкое удаление точки (НОВОЕ)
        Admin->>AdminPanel: Деактивировать точку
        
        AdminPanel->>Admin: Подтвердите деактивацию
        Admin->>AdminPanel: Подтверждение
        
        AdminPanel->>Backend: Деактивация точки<br/>{location_id}
        Backend->>DB: Обновление статуса<br/>Статус: active → inactive<br/>✅ Логирование: деактивация точки
        DB->>Backend: Точка деактивирована
        Backend->>AdminPanel: Точка деактивирована
        
        AdminPanel->>Admin: ✅ Торговая точка деактивирована<br/>(данные сохранены в базе)
        
    else ✅ Активация точки (НОВОЕ)
        Admin->>AdminPanel: Активировать точку
        
        AdminPanel->>Backend: Активация точки<br/>{location_id}
        Backend->>DB: Обновление статуса<br/>Статус: inactive → active<br/>✅ Логирование: активация точки
        DB->>Backend: Точка активирована
        Backend->>AdminPanel: Точка активирована
        
        AdminPanel->>Admin: ✅ Торговая точка активирована
        
    else ✅ Фильтрация (НОВОЕ)
        Admin->>AdminPanel: Фильтр: [Все/Активные/Неактивные]
        
        AdminPanel->>Backend: Запрос с фильтром
        Backend->>DB: Получение точек по фильтру
        DB->>Backend: Отфильтрованный список
        Backend->>AdminPanel: Список точек
        
        AdminPanel->>Admin: Отфильтрованный список + Карта
    end
```

**Изменения:**
- ✅ **Мягкое удаление** - точки не удаляются из базы, а деактивируются (статус: active/inactive)
- ✅ **Уникальность названия** - название точки должно быть уникальным
- ✅ **Визуализация карты** - все точки отображаются на карте с маркерами
- ✅ **Цветовая индикация:** активные точки - зеленые, неактивные - серые
- ✅ **Фильтрация:** просмотр всех, только активных или только неактивных точек
- ✅ **Возможность активации** деактивированных точек
- ✅ **Логирование** - все действия с точками логируются

## 2. ХОСТЕС

### Особенности работы хостес

**Важно:**
- Хостес - это отдельное агентство (отдельная юр. компания)

- **НЕТ фискализации** (не наша касса)
- **НЕТ создания документов продажи** в нашей 1С

5. Проводить Guided Trail (Презентацию) - расширенная версия с лайками и опросниками

## 3. МОБИЛЬНЫЙ ПРОДАВЕЦ

### Особенности работы мобильного продавца

**Важно:**
- **❌ НЕТ процессов привязки устройства** (3.2 и 3.3 удалены)
- **Причина:** У мобильных продавцов устройства привязываются **автоматически при продаже** (процесс 3.1, шаг 6)
- Не может быть случая, когда устройство не привязано - оно всегда привязывается в момент продажи

**Мобильный продавец может:**
1. Продавать товары (только онлайн) - **с автоматической привязкой устройства**
2. Регистрировать пользователей (см. процесс 4.1)
3. ❌ **НЕ МОЖЕТ привязывать устройства отдельно** - только через продажу
4. Делать инкасацию
5. Создавать заявки на перемещение товаров
6. Редактировать профиль покупателя (список всех пользователей)
7. Проводить Guided Trail (Презентацию) - расширенная версия с лайками и опросниками
8. Выбирать торговую точку (см. процесс 4.2)

## 4. ОБЩИЕ ПРОЦЕССЫ И ИНТЕГРАЦИИ

### 4.1. ПРОЦЕСС: РЕГИСТРАЦИЯ ПОЛЬЗОВАТЕЛЯ (УНИВЕРСАЛЬНЫЙ)
**🔄 ИЗМЕНЕН** - добавлен признак регистрации + регистрация через паспорт

**Описание:**
- **Универсальный процесс** для регистрации пользователей (используется всеми ролями)
- **Два режима:** онлайн (с OTP) и оффлайн (бумажная форма)
- **Два типа граждан:**
  - **Граждане РК:** ИИН (обязательно)
  - **Не граждане РК:** Номер паспорта (обязательно) + ФИО + Дата рождения + Документ
- **Номер паспорта** - уникальное поле в 1С (как ИИН)
- **Оффлайн режим:** сохранение в локальную БД с последующей синхронизацией
- **Проверка данных:** автоматическая проверка при синхронизации, создание задачи в Bitrix24 при ошибках
- **Онлайн режим:** OTP через SMS, ввод кода = согласие с пользовательским соглашением

**Новые поля:**
- ✅ **registered_by_type:** "hostess" | "seller" | "retail" - тип пользователя, который регистрирует
- ✅ **registered_by_id:** ID пользователя, который регистрирует
- ✅ **passport_number:** номер паспорта (для не граждан РК)

**Логика выбора типа гражданина:**
1. Пользователь выбирает: "Гражданин РК" или "Не резидент РК"
2. Если гражданин РК → поле ИИН (обязательно)
3. Если не резидент РК → поле Номер паспорта (обязательно)
4. Backend автоматически сохраняет:
   - `registered_by_type` - тип пользователя (hostess/seller/retail)
   - `registered_by_id` - ID пользователя, который регистрирует
5. ✅ **Логирование:** регистрация пользователя логируется

**Использование:**
- Этот процесс используется в:
  - Процессе 2.1, 2.2, 2.4 (хостес)
  - Процессе 3.1, 3.4 (мобильный продавец)
- Вместо дублирования кода просто ссылаемся: "См. процесс 4.1 (Регистрация пользователя)"

- **Онлайн режим:** OTP через SMS, ввод кода = согласие с пользовательским соглашением
